## 운영 규칙

1. `blocked` 소스는 `crawlers/run_all.py` 운영 배치에 넣지 않는다.
2. 약관이나 운영정책이 바뀌면 이 문서와 실행 목록을 같은 PR에서 갱신한다.
3. "공개 페이지", "robots 허용", "로그인 불필요"를 재사용 허가로 해석하지 않는다.
4. 이미지 원본 복제/호스팅, 전문 본문 복제, 사용자 개인정보 수집은 별도 허용 근거 없이는 하지 않는다.
5. Re:Place 화면에는 원문 링크와 최소 검색·비교용 메타데이터만 사용하고, 원문 전체를 대체하는 방향으로 확장하지 않는다.
6. 공식 API/제휴 경로가 확인되면 HTML 수집보다 우선한다.
7. 정책이 불명확한 소스의 요청 빈도는 현재 6시간 운영 배치 수준 이상으로 높이지 않는다.
8. 법적 확정 판단이 필요한 경우 운영자/권리자 확인 또는 전문가 검토를 거친다.

## RPL-044 인플렉서 조사

2026-10-07 공개 HTML이 참조하는 `/static/js/bundle.js`에서 자체 검색 서버
`https://inflexer.net:5000/search`와 `query`, `media`, `type`, `target` 파라미터를 확인했다.
블로그(`BP_`), 방문/제품(`VST`, `SHP`), 전체(`TOTAL`) 조건의 ‘노원’ 표본은
총 113건 중 레뷰 21건, 강남맛집 58건이었다. 이는 검색 표본이며 전체 수집량이 아니다.
`apl_due_dt`(신청 마감)와 `pub_due_dt`(리뷰 마감)는 별개다.

공개 프런트엔드는 인플렉서 서버 내부의 원본 수집 방식, 토큰 사용, 제휴 여부를
노출하지 않는다. 제3자의 표시 사실을 Re:Place의 재사용 허가로 간주하지 않는다.
`scripts/inflexer_probe.py`는 단일 키워드 진단만 수행하며 DB 저장·운영 배치 연결이 없다.
RPL-045에서 사용자의 명시적 지시로 별도 `crawlers/inflexer_revu_crawler.py` 운영 adapter를 추가했다.
미확인 재사용 조건을 확인된 금지로 취급하지 않고 사용자 승인 범위에서 공개 읽기 조회를 진행한다.
새 source `레뷰(인플렉서)`만 별도 활성화하며 권리자 허가 미확인과 조회 범위 제한은 그대로 기록한다.
인플렉서 제공 데이터의 원본 수집 시각과 신청/모집 인원은 확인되지 않으므로 null로 기록한다.
레뷰 원본 목록 API는 무인증 401을 재확인했고 레뷰 운영 상태는 그대로 유지한다.

## 리뷰노트 차단 근거

2026-09-29 확인한 리뷰노트 운영정책에는 자동화된 수단을 이용한 데이터 수집과 회사의 사전 서면 동의 없는 외부 게시/제공을 제한하는 조항이 확인되었다. 따라서 RPL-005부터 운영 배치에서 제외한다.

기존 DB 데이터는 즉시 삭제하지 않는다. RPL-006에서 source status/freshness 정책에 따라 화면 노출 여부와 stale 처리 방식을 정한다.

## 재활성화 조건

기존 직접 API source의 재활성화 기준은 다음과 같이 기록되어 있다.

- 권리자/운영자의 명시적 서면 허용
- 이용 범위가 명확한 공식 API 또는 제휴 인터페이스
- 약관/운영정책 변경으로 현재 사용 방식이 명시적으로 허용되는 경우

확인 없이 단순히 크롤러가 다시 동작한다는 이유로 재활성화하지 않는다.

2026-10-07 사용자가 개인 포트폴리오 용도로 공개 수집·노출을 명시적으로 지시했다.
RPL-046은 이 지시를 반영해 별도 `reviewnote-public-list` source와 공개 UI의 전체
BLOG/BLOG_CLIP 목록 API 페이지를 사용한다. 초기 HTML 한정 수집을 대체한다. 기존 `reviewnote` row와 실패하는 직접 API collector는 활성화하지 않는다.
정책 제한 기록을 삭제하거나 개인 프로젝트라는 이유로 재사용 허가가 있다고 주장하지 않는다.
출시 전 숨김은 새 row의 status=paused, collection_enabled=false, search_enabled=false로 가능하다.

## 아싸뷰 정책·표본 검증 근거

2026-10-03 RPL-041에서 공개 비로그인 GET만 사용해 배송형·구매형·방문형·기자단·결제형 각 1건을 목록 JSON과 상세 페이지로 대조했다.

- 5건 모두 제목, 원본 유형, 신청/모집 수, 마감 시각이 일치했다.
- 배송형·결제형의 블로그 매체가 상세 표시와 일치했다. 구매형·방문형·기자단의 상세 `릴스` 표시는 공통 모델에서 `숏폼(릴스)`로 의도적으로 정규화한다.
- 지역은 방문형·결제형 제목에서 추출했고, 배송형은 `배송`, 기자단은 `전국`이라는 기존 공통 모델 기본값을 사용한다. 기자단 상세 화면에 `전국` 문구가 직접 표시되는 것은 아니다.
- `cp_opt_text`가 `cp_opt_name`을 포함하는 실제 구매형·방문형에서 보상 문구가 중복되는 결함을 확인하고, 더 긴 상위 문구 하나만 남기도록 수정했다.

정책 검토 대상은 `robots.txt`, `policy.php?code=amago_agreement`, `policy.php?code=agreement`, `policy.php?code=privacy`였다. robots.txt는 공개 경로 접근을 허용하지만, 이용약관에는 사전 승낙 없는 서비스 정보의 복제·유통·상업적 이용 및 회사 동의 없는 영리 목적 서비스 이용을 금지하는 조항이 있다. 따라서 기술적 접근 가능성과 별개로 Re:Place 운영 수집·표시는 `paused-policy`를 유지한다.

재검토 조건은 다음 중 하나다.

- 권리자/운영자의 서면 허가
- 재사용 범위가 명시된 공식 API 또는 데이터 인터페이스
- 약관 변경으로 수집·검색 메타데이터 재사용이 명확히 허용되고 운영 검토가 완료된 경우
