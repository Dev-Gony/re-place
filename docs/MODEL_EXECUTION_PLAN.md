# 개발 순서와 모델·추론 배정

작성일: 2026-09-29. 아래는 re:place의 변경 위험도에 따른 권장안이며 모델별 성능을 측정한 벤치마크가 아니다.

## 기본 설정

일반 구현은 **GPT-5.6 Sol / High**. 보안·데이터 의미·트랜잭션·마이그레이션은 **GPT-5.6 Sol / Extra High**. 중요한 설계와 최종 변경 검토에 **GPT-6 Pro**를 별도 사용한다.

[OpenAI 공식 모델 안내](https://help.openai.com/en/articles/20001354-gpt-56-and-gpt-6-pro-in-chatgpt)는 Sol의 Medium/High/Extra High와 Pro 모델 선택을 구분한다. 플랜·워크스페이스에 따라 표시/접근이 달라질 수 있다. GPT-6 Pro에 Sol의 Extra High를 덧붙여 설정하는 것으로 설명하지 않는다. 실제 UI에 있는 모델을 선택하며 모델 변경을 했다고 채팅 문장만으로 가정하지 않는다.

Medium은 의미가 바뀌지 않는 문구·단순 스타일·문서 오탈자 정리에 한정한다. Pro 사용이 코드 실행·시험·사람의 승인·법적 판단을 대체하지 않는다. Pro 접근이 없으면 Extra High로 진행하고 별도 검토와 테스트를 강화한다. 구매나 요금제 변경을 자동 요구하지 않는다.

## 빌드·배포 실행 정책

Vercel Preview는 검증 자원이므로 커밋마다 소비하지 않는다.

1. 이슈 시작 시 main 기준선과 요구사항을 확정한다.
2. 코드·테스트·문서를 기능 단위로 충분히 묶는다.
3. 중간 파일 저장마다 branch ref를 갱신하지 않는다.
4. 가능한 경우 Git blob/tree/commit 객체로 변경을 준비하고 마지막에 branch ref를 한 번만 이동한다.
5. branch push 이후 GitHub CI와 Vercel Preview를 한 차례 실행한다.
6. 실패 시 로그를 먼저 모아 원인을 묶어서 수정하고, 재빌드 횟수를 최소화한다.
7. 문서/테스트 표현만 바뀐 작은 수정은 다음 기능 배치에 합친다.

기본 목표는 **기능 이슈당 Vercel Preview 1회**, 필요한 실패 수정까지 포함해도 최소 횟수다. 빌드 횟수를 줄이기 위해 검증 자체를 생략하지는 않으며, GitHub CI/정적 분석/계약 테스트와 실제 Preview 브라우저 검증의 역할을 구분한다.
