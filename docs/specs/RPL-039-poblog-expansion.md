# RPL-039 포블로그 대형 소스 수집 확장

상태: IN_PROGRESS
Issue: #131
기준 main SHA: 3956c62bb5046e378ea198c5a1a20743c105cd5c

## 문제

Re:Place 운영 수집 플랫폼은 현재 디너의여왕, 미블, 리뷰플레이스, 리뷰어스 4개다. 신규 플랫폼은 유지보수 비용 대비 공급량이 충분한 대형 소스만 추가한다.

2026-10-02 공개 조사에서 포블로그는 모집중 캠페인이 약 870건 수준으로 관측되며, 공개 비로그인 목록에서 숫자형 campaign ID, 방문/배송 유형, 매체, 모집 인원, 제공 내역, 모집 기간을 확인할 수 있다.

기존 `crawlers/poblog_crawler.py`는 구조 진단용 코드만 있고 운영 저장은 하지 않는다.

## 목표

- 공개 비로그인 목록만 사용해 포블로그 수집 계약을 구현한다.
- 첫 화면 일부만 저장하지 않고 추가 캠페인 로딩 방식을 검증한다.
- 공통 Campaign 모델로 정규화한다.
- fixture 회귀 테스트와 fail-closed 조건을 추가한다.
- 수집 범위와 정책 판단을 Source Usage Register에 기록한다.

## 비목표

- 로그인 세션, 쿠키, 사용자 토큰 사용
- 인증 우회
- 캠페인 전문/이미지 원본의 재호스팅
- 검증 전 production source registry 활성화
- 운영 DB 직접 수정

## 선정 기준

신규 플랫폼은 원칙적으로 공개 모집중 캠페인 700건 이상을 1차 확장 대상으로 한다. 그보다 작은 플랫폼은 독점성이나 데이터 품질상 특별한 이유가 없으면 후순위로 둔다.

## 사용자 가치

- 검색 가능한 캠페인 풀 확대
- 방문/배송/블로그/릴스 등 기존 필터의 실효성 확대
- 소형 플랫폼을 무작정 늘리지 않고 유지보수 비용 대비 데이터 공급량을 우선

## 기능 요구사항

1. 포블로그 campaign URL `/campaign/<numeric-id>/`를 안정적인 source ID로 사용한다.
2. title, campaign_type, media_type, recruit_count, region, reward, deadline_at을 공개 목록에서 가능한 범위까지 추출한다.
3. 알 수 없는 값은 추측하지 않고 null/빈 값으로 유지한다.
4. 중복 source ID를 제거한다.
5. 목록 구조가 깨져 0건이 되면 성공 처리하지 않는다.
6. 초기 목록을 넘는 전체 수집 방식이 검증되지 않으면 운영 활성화하지 않는다.
7. 수집 빈도는 기존 6시간 배치보다 높이지 않는다.

## 정책/접근 경계

2026-10-02 확인:
- 공개 목록은 비로그인 접근 가능
- robots.txt는 `User-agent: * / Allow: /`, `/temp/`, `/admin/` 차단
- 공개 약관에서 자동 수집에 대한 명시적 허용은 확인하지 못했으므로 저빈도 최소 메타데이터 수집 전제로 별도 기록
- 공식 API가 확인되면 HTML보다 우선

robots 허용은 상업적 재사용 허가로 간주하지 않는다.
