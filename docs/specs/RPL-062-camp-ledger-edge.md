## 배경

Re:Place V2는 찜 → 내 체험단 → 일정 → 작성·제출 마감 → 정산 흐름을 이미 갖췄다(`docs/V2_COMPLETION.md`).
다음 방향은 이 개인 워크스페이스를 **CampLedger**(체험단·블로그 캠페인 수익·정산·리뷰 추적 도구)로 키우는 것이다.

이번 단계의 제약:

- 외부 사용자를 모집하지 않는다. 검증은 **페르소나 기반 테스트 사용자**로 한다.
- **크롤링은 범위에서 제외**한다. 수집 대상 확대나 크롤러 변경을 하지 않는다. 운영 중인 수집 배치와 코드는 그대로 둔다.
- 기능은 Re:Place 안에 둔다. 별도 브랜드 분리는 페르소나 검증 이후 결정한다.
- 운영 DB에 데이터를 만들지 않는다.

## 원칙: 기술 우위보다 도메인 허점(Edge) 먼저

1. **허점을 먼저 정의한다.** "체험단 관리 앱"은 경쟁력이 아니다. 크리에이터가 실제로 돈과 신뢰를 잃는 지점 하나를 가설로 적는다.
2. **수작업으로 결과부터 확인한다.** DB·계정·대시보드보다 먼저, 사용자가 가진 시트를 넣으면 원하는 진단이 나오는지 확인한다.
3. **로그인 없는 Aha-moment.** 가입 없이 시트를 붙여넣는 즉시 "내가 놓친 돈/발행"이 보이게 한다. 저장·계정은 그 다음 단계다.
4. **좁고 밀도 높은 대상.** 외부 배포 대신 페르소나 4명의 실제 같은 시트로 반복 검증한다.

## 도메인 허점 가설

> 체험단 크리에이터는 캠페인 정보를 시트·메모·플랫폼 마이페이지에 흩어 관리한다.
> 그 결과 (1) **마감이 지났는데 발행하지 않은 건**과 (2) **받기로 한 원고료·페이백을 받지 못한 건**을
> 제때 알아차리지 못한다. 플랫폼 패널티와 미수금은 시트에 "적혀는 있지만 계산되지 않은" 상태로 남는다.

### 왜 허점인가

- 플랫폼 마이페이지는 **자기 플랫폼 캠페인만** 보여준다. 여러 플랫폼·직접 협찬·숏폼 협업을 합친 시야가 없다.
- 시트는 **기록은 하지만 판단하지 않는다.** "오늘 기준 마감 지남 + URL 비어 있음"을 자동으로 계산하지 않는다.
- 정산은 **약속과 실제가 분리**되어 있다. 원고료 5만 원 약속, 익월 10일 지급, 실제 입금 3만 원 같은 차이는 통장과 시트를 대조해야만 보인다.
- 날짜·금액 표기가 사람마다 제각각이다(`11/3`, `2026.11.03`, `5만원`, `50,000`, `O/X`). 그래서 시트 함수를 걸기 어렵다. 이 **지저분한 데이터 정규화**가 기술적 해자다.

### 성공 기준 (페르소나 검증으로 측정)

| 지표 | 기준 |
|---|---|
| 첫 진단까지 시간 | 붙여넣기 후 1초 이내, 로그인 0회 |
| 필드 인식률 | 페르소나 샘플 시트의 핵심 열(캠페인·마감·URL·지급액·지급일·입금) 자동 인식 100% |
| 누락 탐지 | 페르소나 시트에 심어 둔 누락(마감 지남·미발행, 지급일 지남·미입금)을 모두 탐지 |
| 오탐 | 취소·미선정 행, 이미 입금 완료된 행을 누락으로 표시하지 않음 |
| 해석 불가 표기 | 읽지 못한 날짜·금액은 "확인 필요"로 따로 보여주고 조용히 버리지 않음 |

## 페르소나

실존 인물이 아닌 테스트용 가상 사용자다. 각 페르소나는 `lib/ledger-samples.ts`의 샘플 시트와 E2E 시나리오로 이어진다.

### A. 직장인 맛집 블로거 (`office-blogger`)

- 월 6~10건, 방문형 맛집·카페 위주. 리뷰노트·디너의여왕·강남맛집 등을 섞어 쓴다.
- 구글 시트: `업체명 | 플랫폼 | 방문일 | 포스팅 마감 | 포스팅 URL | 제공 내역 | 비고`
- 날짜를 `11/3`, `11.12`처럼 연도 없이 쓴다. 제공 내역은 `2인 코스 (8만원 상당)`처럼 문장이다.
- 놓치는 지점: 퇴근 후 몰아서 쓰다가 **마감 하루 지난 건**을 놓친다. 원고료는 거의 없다.

### B. 숏폼·블로그 다채널 크리에이터 (`multi-channel`)

- 블로그+인스타 릴스+유튜브 쇼츠. 배송형 제품과 **원고료·페이백**이 많다.
- 엑셀: `캠페인 | 채널 | 업로드 마감 | 링크 | 원고료 | 지급예정일 | 입금액 | 정산`
- 금액을 `5만`, `150,000원`, `3.5만`으로 쓴다. 정산 열에 `O`, `X`, `대기`, `부분입금`이 섞인다.
- 놓치는 지점: **지급 예정일이 지났는데 입금이 안 된 건**과 **일부만 입금된 건**.

### C. 포인트·제공형 위주 대학생 (`points-student`)

- 배송형 소액 제품과 포인트 캠페인 위주. 시트를 대충 쓴다.
- 메모 수준 표: `제품 | 사이트 | 마감 | url | 포인트`
- 날짜를 `11월 20일`, `2026/11/25`로 쓰고 URL 칸을 자주 비운다. 미선정·취소 행을 지우지 않고 남긴다.
- 놓치는 지점: **URL을 안 적어서** 발행했는지 본인도 헷갈린다. 취소 건이 섞여 있다.

### D. 소규모 셀러·체험단 모집자 (`small-seller`)

- 자사 제품 체험단을 직접 모집해 크리에이터 10~20명에게 제품과 원고료를 준다. **반대편(지급하는 쪽)** 시점이다.
- 시트: `리뷰어 | 채널 | 발송일 | 리뷰 마감 | 리뷰 링크 | 원고료 | 지급일 | 지급완료`
- 같은 리뷰어가 중복 등록되는 실수가 있다. 링크 칸에 `블로그 올림` 같은 URL이 아닌 메모를 적는다.
- 놓치는 지점: **리뷰를 안 올린 리뷰어**, 줘야 하는데 **아직 안 준 원고료**, 중복 행.

## v1 요구사항과 현재 기능 대조

| CampLedger v1 요구 | Re:Place 현재 | 갭 | 다룰 단계 |
|---|---|---|---|
| 캠페인 기록 | `user_campaign_records` (연결·직접 등록) | 직접 등록이 찜 흐름 뒤에 숨어 있음 | RPL-064 |
| 작성·제출 마감 | tasks + 작성·제출 마감 보드 | 없음 | - |
| 지급 약속 금액 | `user_campaign_settlements.expected_*` | 없음 | - |
| **지급 예정일** | 없음 | 약속 날짜가 없어 "지급일 지남"을 계산할 수 없음 | RPL-064 |
| 실제 입금 | `actual_*_received_*` | 없음 | - |
| **발행 URL** | 없음 (`link`는 캠페인 원문 링크) | 발행 여부를 판단할 데이터가 없음 | RPL-064 |
| **누락 진단** | 대시보드에 지연 일정·미정산 합계만 있음 | "마감 지남+미발행", "지급일 지남+미입금"을 행 단위로 보여주지 않음 | RPL-063, RPL-064 |
| **기존 시트 가져오기** | 없음 | 시트 사용자의 진입 장벽 | RPL-063 (진단), RPL-064 (저장) |
| 발행 URL 생존 확인 | 없음 | 서버가 임의 URL을 요청하면 SSRF 위험이 있음 | v1에서는 형식 검사만. 별도 결정 |
| 로그인 없는 체험 | 없음 (`/my`는 로그인 필요) | Aha-moment 경로 없음 | RPL-063 |

## 위험과 롤백

- 위험: 페르소나는 가설이므로 실제 사용자 시트와 다를 수 있다. 리포트에 "페르소나 기반, 실사용 검증 아님"을 명시한다.
- 롤백: 문서 변경만 있으므로 revert로 충분하다.
