# RPL-052: 내 체험단 생성 폼 중복 제출 방지

## 배경

내 체험단의 수동 기록, 일반 할 일, 작성·제출 마감 생성 폼은 네트워크 요청 중에도 다시 제출할 수 있다. 수동 기록은 서버 중복 제거가 없어 반복 클릭 시 동일 기록이 여러 개 생길 수 있고, 사용자는 저장 진행 여부를 알 수 없다.

## 범위

- 세 생성 흐름에 동기식 재진입 lock과 화면 pending 상태를 추가한다.
- 요청 중 제출 버튼을 비활성화하고 진행 문구와 aria-busy를 표시한다.
- 성공한 요청만 폼을 초기화하거나 닫는다.
- 실패한 요청은 기존 입력과 오류 안내를 유지한다.
- Calendar와 Settlement에서 이미 사용하는 pending 상호작용 패턴과 맞춘다.

## Acceptance Criteria

1. 각 생성 handler는 요청 중 추가 submit을 API 호출 전에 차단한다.
2. 각 폼은 pending 중 aria-busy=true이고 제출 버튼이 disabled다.
3. 버튼에 추가 중 또는 저장 중 문구가 표시된다.
4. 성공 시에만 폼이 초기화된다.
5. 실패하면 입력이 유지되고 기존 오류 안내가 표시된다.
6. 전체 test, lint, production build, Preview가 통과한다.

## 안전 경계

- 운영 DB나 실제 사용자 기록을 수정하지 않는다.
- 인증 우회 코드, 테스트 UI route, 신규 계정·권한·외부 연동을 추가하지 않는다.
