# RPL-058: 기록 생성과 정산 상태의 즉시 동기화

## 배경

`/my`에서 즐겨찾기 캠페인이나 직접 입력 기록을 만들면 기록 행은 POST 응답으로 즉시 반영되지만, 정산 행은 전체 workspace GET을 한 번 더 호출해 갱신한다. 기록 저장 뒤 이 후속 조회가 실패하면 정산 화면만 새로고침 전 상태로 남는다. 또한 즐겨찾기 추가 버튼은 응답을 받기 전까지 잠기지 않아 같은 캠페인에 중복 요청을 보낼 수 있다.

## 목표

- 기록 생성 응답에 기록과 해당 기록의 완전한 정산 읽기 모델을 함께 반환한다.
- 생성 성공 뒤 별도 workspace 재조회 없이 기록과 정산 상태를 즉시 반영한다.
- 기존 정산 값이 있는 연결 기록을 다시 upsert하더라도 정산 입력을 보존한다.
- 같은 즐겨찾기 캠페인의 연속 추가 요청을 동기식 잠금으로 한 건만 허용한다.
- 서로 다른 캠페인의 생성 응답 순서가 바뀌어도 모든 기록과 정산 행을 보존한다.
- 직접 등록 실패 시 폼과 입력값을 유지한다.
- 실제 인증이나 운영 DB 없이 mock 응답을 사용하는 DOM fixture를 CI에 추가한다.

## Acceptance Criteria

1. 연결 기록과 직접 기록 POST 응답은 `item`과 `settlement`를 함께 포함한다.
2. 생성 응답의 정산 항목은 레코드 표시 정보, 사용자 정산 입력, 원본 캠페인 금액을 모두 포함한다.
3. 생성 성공 뒤 `/api/v1/me/workspace`를 호출하지 않고 기록과 정산 UI가 갱신된다.
4. 동일 즐겨찾기 추가 버튼을 연속 클릭해도 POST 요청은 한 건만 발생한다.
5. 서로 다른 두 즐겨찾기 생성 응답이 역순으로 끝나도 두 기록과 정산 행이 모두 남는다.
6. 직접 등록 실패 뒤 폼이 닫히거나 입력값이 초기화되지 않는다.
7. DOM fixture는 성공, 실패, 중복 클릭, 역순 응답을 격리된 mock fetch로 검증한다.
8. lint, Node/Python tests, typecheck, production build, CI와 Preview 결과를 기록한다.

## 범위 밖

- 운영 DB 스키마와 기존 운영 데이터를 변경하지 않는다.
- 인증, 권한, 환경변수, 요금제, 외부 연동을 변경하지 않는다.
- 공개 테스트 route나 인증 우회 수단을 추가하지 않는다.
- 수집 범위를 확대하지 않으며 SEBICON 중단 상태를 건드리지 않는다.
