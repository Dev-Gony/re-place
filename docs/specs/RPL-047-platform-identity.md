## 문제

체험단 찾기에는 여러 운영 플랫폼의 캠페인이 한 목록에 섞여 있지만, 현재 플랫폼 필터와 목록 배지는 모두 같은 중립색이다. 사용자는 플랫폼명을 매번 읽어야 하고, 특히 모바일의 촘촘한 카드에서는 원하는 출처를 빠르게 구분하기 어렵다.

## 목표

플랫폼명 텍스트를 유지하면서 작은 점, 옅은 배경과 테두리로 출처를 빠르게 식별한다. 같은 공통 메타데이터를 플랫폼 필터, 목록 카드, 상세 패널에 사용해 색상 불일치를 막는다.

## 비목표

- 카드 전체 배경 또는 탐색 화면의 큰 면적을 플랫폼색으로 채우지 않는다.
- 수집기, 운영 DB, source registry, 외부 연동 또는 환경변수를 변경하지 않는다.
- 불명확한 플랫폼 대표색을 임의로 만들지 않는다.

## 사용자 흐름

1. 사용자가 체험단 찾기에서 플랫폼명과 함께 작은 대표색 표식을 본다.
2. 플랫폼 필터를 선택하면 같은 대표색의 옅은 배경, 테두리와 체크 표시로 선택 상태를 확인한다.
3. 필터 결과의 목록 카드와 상세 패널에서 같은 플랫폼 표식을 확인한다.
4. 모바일에서도 긴 플랫폼명이 잘리지 않고 가로 스크롤 없이 필터와 카드를 사용한다.

## 요구사항

### 기능

- [x] 강남맛집은 주황, 레뷰 계열은 보라, 리뷰노트 계열은 초록으로 표시한다.
- [x] 디너의여왕은 공식 사이트의 분홍, 리뷰어스는 공식 사이트의 파랑 계열을 사용한다.
- [x] 검정/흰색 로고를 사용하는 미블·리뷰플레이스와 알 수 없는 플랫폼은 중립색을 사용한다.
- [x] 원본 source 이름의 괄호 표기와 관계없이 동일 브랜드는 같은 색을 사용한다.

### 데이터 / API

- [x] 기존 캠페인·source registry 계약에 영향 없음
- [x] DB migration 불필요
- [x] 외부 API / 비용 영향 없음
- [x] 인증 / 권한 영향 없음

### UI / UX

- [x] 플랫폼명 텍스트를 항상 유지하고 색만으로 플랫폼이나 선택 상태를 전달하지 않는다.
- [x] 선택 상태는 체크 표시와 글자 굵기로도 구분한다.
- [x] 키보드 포커스와 비활성 상태를 명확히 표시한다.
- [x] 전경/옅은 배경 조합은 WCAG AA 일반 텍스트 대비 4.5:1 이상이다.
- [ ] desktop / mobile에서 긴 이름과 가로 넘침을 확인한다.
- [x] loading / empty / error 동작은 기존 계약을 유지한다.

## 구현 계획

1. `lib/platform-brand.ts`에 alias, 색상, 근거를 포함한 공통 메타데이터를 추가한다.
2. 플랫폼 배지 컴포넌트를 목록·상세·적용 중 필터에 재사용하고 필터도 같은 CSS 변수로 렌더링한다.
3. 접근성 대비·alias·렌더 연결 회귀 테스트와 브라우저 QA를 수행한다.
