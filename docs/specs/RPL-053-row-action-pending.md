# RPL-053: 행 단위 조작 pending과 중복 요청 방지

## 배경

내 체험단의 할 일 완료/완료 취소, 할 일 삭제, 체험단 기록 삭제는 네트워크 요청 중에도 같은 조작을 다시 실행할 수 있다. 빠른 반복 클릭은 동일한 API 요청을 중복 전송하고, 먼저 성공한 삭제 뒤의 요청이 실패하면서 실제 상태와 어긋난 오류 안내를 만들 수 있다.

## 범위

- 할 일 ID별로 완료 상태 변경과 삭제 요청을 하나의 pending registry에서 관리한다.
- 요청 중인 할 일의 조작 버튼만 비활성화하고 진행 상태를 표시한다.
- 같은 할 일이 캘린더 마감 보드와 할 일 목록에 함께 보이면 양쪽 조작을 함께 잠근다.
- 체험단 기록 삭제는 기록 ID별로 중복 요청을 막는다.
- 기록 삭제 중에는 확인 창을 닫거나 다시 제출하지 못하게 하고 aria-busy를 노출한다.
- 성공과 실패 모두에서 pending 상태를 해제한다.

## Acceptance Criteria

1. 같은 ID의 조작은 첫 요청이 끝나기 전에는 두 번째 API 호출을 시작하지 않는다.
2. 서로 다른 ID의 조작은 독립적으로 시작할 수 있다.
3. 할 일 요청 중에는 해당 행과 마감 보드의 완료 버튼이 비활성화된다.
4. 기록 삭제 요청 중에는 취소, 배경 닫기, 삭제 재실행이 차단된다.
5. 요청 실패 뒤에는 해당 행을 다시 조작할 수 있고 기존 오류 안내를 유지한다.
6. 격리 fixture 테스트, 전체 test, lint, production build, Preview 결과를 기록한다.

## 범위 밖

- 운영 DB 또는 실제 사용자 기록을 수정하지 않는다.
- 인증 우회용 테스트 route나 계정을 추가하지 않는다.
- 수집기, 외부 연동, 권한, 환경 변수, 과금 설정을 변경하지 않는다.
- 중단 상태인 세빅콘 수집을 변경하지 않는다.
