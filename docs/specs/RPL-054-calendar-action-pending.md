# RPL-054: 달력 작업별 pending과 편집 상태 보존

## 배경

전용 달력 화면은 생성, 수정, 완료, 삭제 요청을 하나의 React boolean으로 제어한다. state가 화면에 반영되기 전의 연속 조작은 같은 요청을 다시 시작할 수 있고, 한 작업의 요청이 다른 작업의 버튼까지 모두 비활성화한다. 수정 실패 뒤 사용자가 입력한 값과 편집 상태를 유지한다는 회귀 보장도 없다.

## 범위

- 일정 생성에는 동기식 재진입 lock과 전용 pending 상태를 사용한다.
- 일정 수정, 완료 전환, 삭제는 task ID별 pending registry를 공유한다.
- 같은 task의 경쟁 조작은 차단하고 다른 task는 독립적으로 조작할 수 있게 한다.
- 모바일 agenda, 주간/전체 목록, 다가오는 일정에서 같은 task pending 상태를 공유한다.
- 수정 요청 중에는 편집 폼의 제출과 취소를 잠근다.
- 수정 성공 뒤에만 편집 폼을 닫고 실패 시 입력과 편집 상태를 유지한다.

## Acceptance Criteria

1. 일정 생성은 첫 요청이 끝나기 전 중복 submit을 시작하지 않는다.
2. 같은 task ID의 수정, 완료, 삭제는 첫 요청이 끝나기 전 다시 실행되지 않는다.
3. 서로 다른 task ID는 독립적으로 pending이 될 수 있다.
4. 요청 중인 task의 모든 달력 표현에서 관련 조작만 비활성화된다.
5. 수정 실패 시 편집 ID와 uncontrolled 입력을 유지해 재시도할 수 있다.
6. 성공과 실패 모두에서 pending 상태를 해제한다.
7. 격리 fixture 테스트, 전체 test, lint, production build, Preview 결과를 기록한다.

## 범위 밖

- 운영 DB 또는 실제 사용자 기록을 수정하지 않는다.
- 인증 우회 route나 테스트 계정을 추가하지 않는다.
- API, DB schema, 권한, 환경 변수, 외부 연동, 수집원을 변경하지 않는다.
- 중단 상태인 세빅콘 수집을 변경하지 않는다.
